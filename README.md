# SIH26117 — Sovereign AI Workbench

> **Intelligence, kept on-site.**

A secure, self-hosted, agentic AI workbench designed for organizations that need to use AI on sensitive operational and regulatory information without sending that information to external cloud services.

The system combines a modern React frontend with a local FastAPI backend, Retrieval-Augmented Generation (RAG), an agentic workflow, document retrieval, and locally hosted open-weight models through Ollama.

---

## Overview

**SIH26117 — Sovereign AI Workbench** is designed around a simple principle:

> Sensitive organizational knowledge should remain within the organization's infrastructure.

The workbench provides a conversational interface through which users can:

* Ask questions about organizational SOPs, regulations, and technical documents
* Retrieve relevant evidence from the internal knowledge base
* Receive answers generated by a local AI model
* View the reasoning/tool-use steps performed by the agent
* Search the organization's knowledge base
* Generate Word and Excel documents through agent tools
* Run the entire AI inference pipeline locally

The architecture is designed to support an eventual **air-gapped deployment**, where no organizational data needs to leave the premises.

# Local Setup

## 1. Clone the repository

```bash
git clone <repository-url>
cd SIH26117-Workbench
```

---

# 2. Set up the backend

From the repository root:

```bash
python -m venv venv
```

### Windows

```bash
venv\Scripts\activate
```

### Linux / macOS

```bash
source venv/bin/activate
```

Install the Python dependencies:

```bash
pip install -r requirements.txt
```

---

# 3. Install and configure Ollama

Install Ollama from its official distribution.

Pull the default model:

```bash
ollama pull llama3.2:3b
```

Verify that the model is available:

```bash
ollama list
```

The backend expects Ollama to be available locally at:

```text
http://localhost:11434
```

The default model is:

```text
llama3.2:3b
```

The model can be changed in:

```text
backend/main.py
```

---

# 4. Start the backend

From the repository root:

```bash
cd backend
```

Make sure the virtual environment is activated, then run:

```bash
uvicorn main:app --reload
```

The backend will be available at:

```text
http://localhost:8000
```

FastAPI's interactive API documentation is available at:

```text
http://localhost:8000/docs
```

Health check:

```text
http://localhost:8000/health
```

A successful health check returns:

```json
{
  "status": "FastAPI is running"
}
```

---

# 5. Configure the frontend

Open a second terminal.

From the repository root:

```bash
cd frontend
```

Install the frontend dependencies:

```bash
npm install
```

Create a local environment file:

```text
frontend/.env.local
```

Add:

```env
VITE_API_URL=http://localhost:8000
VITE_USE_MOCK_DATA=false
```

`.env.local` is intentionally ignored by Git and should not be committed.

---

# 6. Start the frontend

Run:

```bash
npm run dev
```

Vite will provide a local URL, normally:

```text
http://localhost:5173
```

Open that URL in your browser.

# Git & Generated Files

The repository intentionally ignores local/generated files such as:

```text
venv/
node_modules/
.env
.env.local
__pycache__/
chroma_db/
generated/
dist/
build/
*.docx
*.xlsx
*.pptx
*.log
```

Do not commit:

* API keys or credentials
* `.env.local`
* Python virtual environments
* `node_modules`
* ChromaDB/local vector-store files
* Generated test documents
* Build output

The `.env.example` file should be used to document required frontend environment variables without exposing local configuration.

# Security & Sovereignty

The system is designed around an on-premise AI architecture.

Instead of sending organizational data to external AI APIs:

```text
User Data
    │
    ▼
Internal Backend
    │
    ├── Internal Knowledge Base
    │
    └── Local AI Model
             │
             ▼
          Response
```

The intended production architecture can run entirely within an organization's controlled infrastructure.

This allows sensitive SOPs, regulations, engineering documents, and operational information to remain within the organization's network.

For production deployment, CORS, authentication, network access controls, model access, file handling, and other security controls must be hardened beyond the current local-development configuration.

# Troubleshooting

## Backend does not start

Verify that the virtual environment is active:

```bash
venv\Scripts\activate
```

Then reinstall dependencies:

```bash
pip install -r requirements.txt
```

Run:

```bash
uvicorn main:app --reload
```

---

## Ollama connection error

Check:

```bash
ollama list
```

and ensure the required model exists:

```text
llama3.2:3b
```

If it does not:

```bash
ollama pull llama3.2:3b
```

---

## Frontend cannot connect to backend

Verify that FastAPI is running:

```text
http://localhost:8000/health
```

Then check:

```text
frontend/.env.local
```

contains:

```env
VITE_API_URL=http://localhost:8000
VITE_USE_MOCK_DATA=false
```

Restart the Vite development server after changing environment variables.

---

## Frontend dependencies are missing

From `frontend/`:

```bash
npm install
```

Then:

```bash
npm run dev
```
